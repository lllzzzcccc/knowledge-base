## Summary

知乎专栏文章，用"工厂—车间—生产线—工人"的类比系统讲解 [[Process]] 与 [[Thread]] 的本质区别。全文覆盖：进程地址空间结构（代码区/数据区/堆栈区）、进程上下文构成与切换开销、线程的私有资源与共享资源（含 C++ 代码示例验证五类共享）、进程与线程的四维对比、并发与并行的时间片轮转原理，以及 CPU/IO 密集型任务的多进程/多线程选型建议。

## Key Claims

- 进程是程序在专属地址空间内的动态执行实例，是 OS **资源分配**的基本单位；线程是 CPU **调度执行**的基本单位。
- 进程地址空间分三区：代码区（指令）、数据区（全局/静态变量）、堆栈区（栈管函数调用、堆管动态分配）。
- 进程上下文 = CPU 寄存器 + 进程状态（由 PCB 管理）+ 地址空间信息（页表/段表）+ 内核栈与用户栈；线程上下文仅含运行栈、程序计数器（PC）、部分寄存器。
- 因进程上下文包含重量级地址空间信息，**进程切换开销通常是线程切换的 10~100 倍**——这是线程存在的核心原因。
- 线程共享所属进程的五类资源：代码区、数据区（全局/静态变量）、堆区（malloc/new）、文件描述符、信号处理方式——均有 C++ 示例代码验证。
- 一个线程崩溃可能导致整个进程被 OS 杀掉；多进程因地址空间隔离而更健壮。
- 单核 CPU 靠**时间片轮转**实现并发（"看似同时"），多核才能实现并行（"真正同时"）。
- CPU 密集型任务建议多进程或少线程（避免切换浪费）；IO 密集型任务建议多线程（等待 IO 时切换其他线程）。
