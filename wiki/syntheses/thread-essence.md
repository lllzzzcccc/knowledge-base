# 线程的本质:三层剥洋葱

**问题**:线程是历代计算机学者抽象后的概念,它的真实面目是什么?

## 第一层:抽象层(教科书答案)

**线程是 CPU 任务调度和执行的基本单位,是进程内的执行分支**([[Thread]])。全部"私有财产"只有三样:运行栈、程序计数器(PC)、部分寄存器;代码区、数据区、堆、文件描述符、信号处理方式全向所属 [[Process]] 借用。

抽象的核心动作:**把"执行"从"资源"中剥离**——进程回答"谁拥有资源",线程回答"谁在执行"。

## 第二层:硬件层(CPU 不知道线程的存在)

一个物理核任意时刻只有一份寄存器现场(PC、栈指针、通用寄存器)。"多线程并发"在硬件看来只是 OS 周期性**把整个寄存器现场换一份**:换 PC(换指令流)、换栈指针(换函数调用栈)、换通用寄存器(换半成品计算)。

**线程在硬件眼里没有"身体",只有一份执行现场快照。** 线程上下文切换便宜(见 [[ContextSwitch]])就因为换的仅是这几个寄存器;进程切换还要换页表基址、刷 TLB——"换整个内存世界",开销差 10~100 倍。

抽象分界线:**线程 = 控制流 + 现场;进程 = 现场 + 资源环境。**

## 第三层:内核层(Linux 没有"线程"数据结构)

Linux 内核里进程和线程是同一个东西——`task_struct`。唯一区别是一个指针:是否共享 `mm_struct`(地址空间描述符)。`clone()` 通过标志位决定父子任务共享什么:传 `CLONE_VM` 共享地址空间就是线程,否则是新进程。

**"线程"在内核眼里只是"共享了内存描述符的轻量进程"**(lightweight process)。LinuxThreads → NPTL 的演进改的也只是共享细粒度,而非发明新物种。

## 抽象为什么这样画

```
协程   = 现场           (调度权在用户手里,内核无感知)
线程   = 现场 + 内核调度   (共享地址空间)
进程   = 现场 + 资源 + 调度 (地址空间隔离)
```

- **多进程**:隔离好,但切一次换"整个世界"
- **线程**:只切执行现场,资源环境不动——用共享换效率
- **协程**(goroutine、green threads):同一轻量化路线的延续,把"现场"压到只剩栈,调度权从内核交还程序

## 一句话答案

> **线程 = 一份被内核独立调度的执行现场(栈 + PC + 寄存器组),本身不拥有任何资源,只是进程资源容器上插着的多个控制流之一。**

代价写在契约里:共享换来零拷贝通信(直接读写全局变量/堆),但一个线程崩溃整个进程被 OS 杀掉,共享数据需用 [[Semaphore]] 重建秩序。
