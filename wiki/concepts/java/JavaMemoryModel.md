# Java 内存模型 (JMM)

**JMM 是 Java 语言规范定义的并发内存访问协议,不是真实的内存划分。** 它屏蔽硬件差异,规定多线程环境下共享变量何时可见、指令能否重排([[java-memory-and-jmm]])。

## 核心抽象：主内存 + 工作内存

- **主内存(Main Memory)**:所有共享变量存于此,线程均可访问 ≈ 物理内存 ≈ JVM 堆中的实例域/静态域/数组元素
- **工作内存(Working Memory)**:每线程私有,存共享变量的**副本**——**是抽象概念,涵盖高速缓存、写缓冲区、寄存器**
- **操作规则**:线程对变量的所有操作必须在工作内存进行,不能直接读写主内存;线程间传值必须经主内存

线程间通信两步:线程 A 把工作内存中更新后的变量**刷新到主内存** → 线程 B 从主内存**读取**并同步进自己的工作内存。

> 注意:局部变量/方法参数在线程栈中(线程私有),**无可见性问题**;可见性问题只针对堆中的共享变量。

## 为什么需要这个抽象

硬件真相(见 [[thread-essence]] 硬件层):**每个 CPU 核有自己独立的 L1/L2 缓存和写缓冲**。线程改共享变量,新值可能只停在它所在核的缓存里没写回内存,另一核上的线程读到旧值——这就是**可见性问题**。JMM 若在规范里写死"缓存"就绑定了具体硬件,于是用与平台无关的"工作内存"来定义规则。

根源一句话:**可见性的原因是缓存,有序性的原因是编译优化**。

## 三大问题与解决手段

| 问题 | 根源 | JMM 手段 |
|---|---|---|
| 可见性 | CPU 缓存/写缓冲 | `volatile`、锁、`final` |
| 有序性 | 编译器/处理器重排序 | 内存屏障 + happens-before 约束 |
| 原子性 | 复合操作中途被切走 | `synchronized`/锁(监视器) |

重排序三类:编译器优化重排序、指令级并行重排序、内存系统重排序;约束=单线程 as-if-serial + 数据依赖禁止重排 + 多线程插内存屏障。

## happens-before 八条

1. **程序次序**:同线程内前面的操作 hb 于后面的操作
2. **监视器锁**:解锁 hb 于后续对同一锁的加锁([[Semaphore]] 的规范层依据)
3. **volatile**:写 hb 于后面对该变量的读
4. **传递性**:A hb B,B hb C → A hb C
5. **start()**:`ThreadB.start()` hb 于 B 中的任意操作
6. **join()**:B 内任意操作 hb 于 A 从 `join()` 返回
7. **中断**:`interrupt()` 调用 hb 于被中断线程检测到中断
8. **对象终结**:构造完成 hb 于 `finalize()` 开始

## 三层视角定位

```
JMM 主内存   ≈ 物理内存 ≈ JVM 堆中的共享变量([[JvmRuntimeMemory]])
JMM 工作内存 ≈ CPU 缓存 + 写缓冲 + 寄存器([[thread-essence]] 硬件层)
"刷新到主内存" = 缓存一致性动作,不是把数据拷到另一块空间
```

常见误解:画着"每线程一块工作内存"的 JMM 图**不是**地址空间划分——物理上所有线程共享同一地址空间([[AddressSpaceLayout]]),工作内存是缓存系统的问题域抽象。
