# JVM 运行时数据区 (Java 内存结构)

**Java 内存结构 = JVM 对自己那份用户空间的逻辑分区。** 按线程访问特性分两类([[java-memory-and-jmm]]):

```
┌─ 线程共享区(生命周期与 JVM 一致)─────────────┐
│ 堆 Heap:对象实例/数组,GC 主战场(-Xmx/-Xms)     │
│ 方法区:类元信息/常量/静态变量/JIT 代码缓存       │
│   └ 运行时常量池(Class 常量池→符号解析→直接引用) │
└──────────────────────────────────────────┘
┌─ 线程隔离区(生命周期与线程一致)────────────────┐
│ 虚拟机栈:栈帧(局部变量表/操作数栈/动态连接/出口) │
│ 程序计数器:字节码行号指示器,唯一无 OOM 区域      │
│ 本地方法栈:Native 方法服务(HotSpot 与虚拟机栈合一)│
└──────────────────────────────────────────┘
```

## 关键事实

- **虚拟机栈**:每线程一个,栈帧随方法调用入栈/出栈;深度超限抛 `StackOverflowError`;不同线程的栈帧禁止互相引用
- **程序计数器**:字节码行号指示器(**注意是逻辑 PC,非硬件 PC**),线程切换后靠它恢复执行——对应 [[thread-essence]] 硬件层的 PC,但作用域是字节码
- **堆**:逻辑上方法区是它的"一部分"(规范定义),物理上两者分开(方法区别名 Non-Heap);逻辑连续即可,物理可不连续
- **方法区实现演进**:Java 7 及之前 = 永久代(PermGen,在物理堆内);Java 8 起 = **元空间(Metaspace,移入本地内存)**,静态变量与字符串常量池随之移入物理堆
- **直接内存**:NIO 的 `DirectByteBuffer` 引用堆外内存,避免 Java 堆↔Native 堆的来回复制
- **内存总账**:Java 程序内存 = JVM 内存 + 本地内存;本地内存 = 元空间 + 直接内存

## 与 OS 层的映射

JVM 结构层与 [[AddressSpaceLayout]] 完全同构,只是更细:

| JVM 层 | OS 层 |
|---|---|
| 虚拟机栈(每线程) | 每线程一块用户栈(1MB `-Xss`,mmap + guard page) |
| 程序计数器 | 硬件 PC 的字节码版 |
| 堆 + 方法区 | 共享的用户空间(数据区 + 堆) |
| 元空间/直接内存 | 用户空间中向 OS 直接 malloc 的部分 |

方法区/元空间始终**在进程用户空间内**——无论实现怎么演进,都不出 [[AddressSpaceLayout]] 画的那张图。
