# 进程通信 (IPC, InterProcess Communication)

**IPC 是进程之间的信息交换。** 由于每个 [[Process]] 的用户地址空间相互独立、不能直接互访，而内核空间为所有进程共享，因此**进程间通信必须经由内核**（[[six-ipc-mechanisms]]）。

## 低级通信 vs 高级通信

进程同步与互斥本质上也是一种通信——它通过修改信号量使进程建立联系、相互协调，但只传信号量、缺乏传递数据的能力，称为**低级通信**。需要交换大批数据（一批信息或整个文件）时，需使用真正的通信机制（高级通信）。

## Linux 六大通信机制

| 机制 | 本质 | 特点 |
|---|---|---|
| [[Pipe]] | 内核内存中的缓冲区（特殊文件） | 半双工字节流；匿名管道限父子进程 |
| [[MessageQueue]] | 内存中消息的链表 | 按类型随机查询；读写需用户态↔内核态拷贝 |
| [[SharedMemory]] | 两进程页表映射到同一物理区域 | 最快，但需配合同步 |
| [[Semaphore]] | 表示资源数量的变量 + PV 原语 | 低级通信；解决共享内存的冲突 |
| [[Signal]] | 异步事件通知 | 唯一异步机制；与信号量完全不同 |
| [[Socket]] | 封装 TCP/IP 的编程接口 | 唯一能跨网络的机制 |

## 演进逻辑

管道（简单但低效、无格式）→ 消息队列（有格式但拷贝开销大）→ 共享内存（零拷贝最快但会冲突）→ 信号量/PV（为共享内存提供互斥与同步）→ 信号（异步通知）→ Socket（跨网络）。
