# 信号量与 PV 操作 (Semaphore)

信号量是一个表示系统中某种资源数量的变量（如一台打印机 → 初值为 1 的信号量）。用户进程通过 OS 提供的一对原语 **PV 操作**对信号量操作，实现 [[Process]] 互斥与同步（[[six-ipc-mechanisms]]）。属于只传信号量、不传数据的**低级通信**（见 [[IPC]]）。

## PV 操作语义

**P 操作**（申请资源）：信号量减 1。结果 ≥ 0 → 资源足够，继续执行；结果 < 0 → 无可用资源，进程阻塞。

**V 操作**（释放资源）：信号量加 1。加完后 ≤ 0 → 有进程在等待，唤醒其中一个；> 0 → 无人等待，正常继续。

通俗理解：信号量值为 2 表示 2 个资源可用；为 -2 表示有两个进程正在等待该资源。

## 实现互斥（两步走）

1. 定义互斥信号量，初始化 1
2. 把临界区（如对 [[SharedMemory]] 的访问）置于 P 与 V 之间

P、V 必须成对出现：缺 P 则无互斥，缺 V 则资源永不释放、等待进程永不唤醒。

## 实现同步（三步走）

因进程推进的异步性（见 [[ConcurrencyAndParallelism]]），进程执行次序不确定。若 P2 的"代码4"依赖 P1 的"代码2"的结果：

1. 定义同步信号量，初始化为当前可用资源数量
2. 在优先级较高的操作**后**执行 V（释放资源）
3. 在优先级较低的操作**前**执行 P（申请资源）

## 线程级应用

[[Thread]] 共享同一进程的数据区/堆区，C++ 中以 `mutex` + `lock_guard` 实现互斥（[[process-vs-thread]]）。注意与 [[Signal]]（信号）是完全不同的概念。

## 关联概念

- [[SharedMemory]]：最典型的使用场景；[[IPC]]：作为低级通信的归属
- [[Process]] / [[Thread]]：同步互斥的主体
- [[ThreadSynchronization]] — pthread 五类同步原语的工程形态（本文的落地页）
- [[JavaMemoryModel]]：锁的规范层依据——happens-before 监视器锁规则（解锁 hb 于后续加锁，保证临界区修改对下一持有者可见）
