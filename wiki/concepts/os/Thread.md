# 线程 (Thread)

**线程是 CPU 任务调度和执行的基本单位，是进程内的执行分支。** 又称"轻权进程"或"轻量级进程"（[[process-vs-thread]]）。

## 由来

[[Process]] 切换开销太大（见 [[ContextSwitch]]），为解决"轻量化执行"需求，线程作为进程内的执行分支应运而生——类比工厂车间里的"生产线"：共享车间资源，仅保留专属执行工具。

## 三类私有资源（线程上下文）

线程不单独拥有资源，仅保留执行必需的三类私有资源：

1. **运行栈**：函数局部变量、调用参数，每线程独立，避免数据干扰
2. **程序计数器（PC）**：下一条指令地址，确保切换后能续上执行
3. **部分寄存器**：通用寄存器、栈指针

对比进程上下文（含地址空间信息），线程上下文不含地址空间信息，切换时只需保存/加载少量数据，开销极低。

## 共享的进程资源（五类）

同一进程内的线程共享（均有 C++ 示例验证）：

1. **代码区**：所有线程可执行同一函数
2. **数据区**：全局变量、静态变量（同一内存地址）
3. **堆区**：malloc/new 动态分配的内存（持指针即可读写）
4. **文件描述符**：打开的文件、socket 连接
5. **信号处理方式**：进程注册的信号回调对所有线程生效

> 共享的数据区/堆区即 [[JavaMemoryModel]] 所说的"主内存共享变量"（实例域/静态域）：物理上同址，但每核缓存可能让线程读到旧值——可见性问题由此而来。

## 稳定性代价

线程共享进程资源，**一个线程崩溃可能导致整个进程被 OS 杀掉**；多进程因地址空间隔离而更健壮。共享数据区/堆区需要 [[Semaphore]]（互斥锁）保护。

## 阻塞 ≠ 挂起（[[claude-concurrency-io-session]]）

口语上"阻塞了=挂起了"大家能听懂，但严格讲是两个正交概念：

| | 阻塞 (blocked) | 挂起 (suspend) |
|---|---|---|
| 管的是 | **CPU 调度** | **内存管理** |
| 意思 | 线程在**等某个事件**（I/O、锁），挂到 fd 等待队列，事件来了转就绪 | 进程映像被**换出到磁盘（swap）**，不占内存 |
| 谁触发 | 通常是线程自己 | 通常是操作系统（内存紧张） |

注意两个坑：
- Java `Thread.suspend()` 是被废弃的**他人强暂停**，暂停时不释放锁，会死锁——与"阻塞等资源"完全是两码事。
- Java `Thread.State.BLOCKED` 特指"等 synchronized 锁"；**阻塞在 socket I/O 的线程 `jstack` 里常显示 `RUNNABLE`**（JVM 认为在 native 代码里执行 read() 就是可运行的），排查时容易误判。

## 任务选型

- CPU 密集型任务：多进程或少线程，避免频繁切换浪费
- IO 密集型任务：多线程，线程等待 IO 时 CPU 切到其他线程
